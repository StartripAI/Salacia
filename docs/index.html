The Shift

This is not another coding agent.

Salacia is the harness between your repository and the agent you already use.

Agent alone

  • 🔍It must rediscover the repo every run
  • 🔄Execution and judgment are mixed together
  • ❓“Looks good” becomes the promotion policy
  • 🧾Benchmarks and product runs speak different languages

Agent + Salacia

  • 🗺️ContextPack gives it a bounded map
  • ⚖️JudgeLoop decides accept/reject/blocked
  • 🧪Verification is mandatory, not optional
  • 📦Runtime, eval, and release reuse the same evidence

How It Works

Four steps. One harness.

The public flow is now `init -> design -> run -> judge/trace`.

1

Write `program.md`

Declare the goal, mutable surface, verification, and promotion policy.

npx salacia init
2

Build context

Compile the program into a blueprint and build a bounded ContextPack.

salacia design
3

Run the agent

Dispatch the agent in an isolated workspace with the generated context.

salacia run
4

Judge and inspect

Accept, reject, or block the patch, then inspect the trace and evidence.

salacia judge && salacia trace

Your repo stays the source of truth.
Your agent gets a harness.
